# ClearSpace — доска для репетиторов

## Описание проекта

ClearSpace — это клиент-серверное приложение для совместной работы на виртуальной доске в реальном времени. Система ориентирована на проведение дистанционных занятий, в первую очередь по математике, однако архитектура предполагает возможность дальнейшего расширения под другие школьные предметы.

Клиентская часть разрабатывается с использованием Qt. Сервер реализуется на Boost (Boost.Asio). И клиент, и сервер являются многопоточными. Логика приложения покрывается модульными тестами: для серверной части используется GoogleTest, для клиентской — Qt Test.

Проект разрабатывается с расчётом на расширяемость. Первая версия представляет собой простую, но корректно синхронизируемую рисовалку с поддержкой нескольких участников и отображением их курсоров.

## Назначение системы

Система предназначена для совместного рисования и объяснения материала в режиме реального времени. Несколько пользователей могут подключаться к одной доске, видеть действия друг друга и одновременно вносить изменения.

## Общая концепция работы

Каждая доска существует в рамках комнаты (room). Пользователь подключается к серверу и либо создаёт новую комнату, либо входит в существующую по идентификатору. Все участники комнаты работают с единым состоянием доски.

Синхронизация выполняется не через передачу изображения, а через передачу событий. Событие — это атомарное изменение состояния доски: начало штриха, добавление точки, завершение штриха, очистка, перемещение курсора и т.д. Сервер принимает события от клиента и рассылает их всем участникам комнаты.

## Функциональные требования (MVP)

### Подключение к серверу

Клиент должен позволять пользователю указать адрес сервера и установить TCP-соединение. В случае ошибки подключения пользователь получает уведомление. При успешном подключении клиент переходит в состояние готовности к входу в комнату.

### Работа с комнатами

Система поддерживает создание новой комнаты и подключение к существующей по идентификатору. Несколько клиентов могут находиться в одной комнате одновременно. Количество участников не ограничивается двумя; архитектура рассчитана на произвольное число подключённых пользователей в рамках одной сессии.

При входе в комнату клиент получает текущее состояние доски и отображает его целиком. Новый участник видит всё, что было нарисовано до его подключения.

### Рисование на доске

Клиент поддерживает инструмент «перо». Пользователь может:

- начать штрих нажатием кнопки мыши,
- добавлять точки при перемещении курсора,
- завершить штрих при отпускании кнопки.

Каждый штрих имеет цвет и толщину. Выбор цвета и толщины осуществляется из фиксированного набора значений. Новые штрихи используют выбранные параметры, уже нарисованные объекты не изменяются.

### Синхронизация между участниками

При рисовании клиент отправляет на сервер события, описывающие изменения. Сервер пересылает их всем участникам комнаты. Остальные клиенты воспроизводят изменения локально.

Порядок событий сохраняется. При одновременном рисовании несколькими участниками их штрихи корректно отображаются у всех подключённых клиентов.

### Отображение курсоров участников

Каждый подключённый клиент имеет уникальный идентификатор. При движении мыши по области доски клиент отправляет серверу информацию о текущей позиции курсора в координатах доски.

Сервер пересылает обновления другим участникам. Каждый клиент отображает курсоры всех остальных пользователей. При отключении участника его курсор исчезает с доски.

Частота отправки координат ограничивается, чтобы избежать перегрузки сети. Передаётся текущее положение, а не траектория движения.

### Очистка доски

Клиент может инициировать очистку доски. Это действие оформляется как событие и рассылается всем участникам. После очистки текущее состояние доски становится пустым для всех клиентов.

### Отключение

При разрыве соединения сервер корректно удаляет клиента из комнаты и уведомляет остальных участников о его выходе. Работа других пользователей не должна нарушаться.
